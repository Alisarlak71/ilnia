# چک‌لیست امنیت ایلنیا

این فهرست را **قبل از انتشار** و **بعد از هر تغییر در `.env` روی هاست** مرور کن. بیشترش را دستور زیر خودکار چک می‌کند:

```bash
php artisan ilnia:security-check
```

- ✗ یعنی باید درست شود و سایت هنوز آمادهٔ انتشار نیست.
- ! یعنی بهتر است بررسی شود.
- ✓ یعنی درست است.

این دستور مقدار رمزها را نشان نمی‌دهد و فقط بودن یا نبودنشان را چک می‌کند.

## ۱. `.env` تولید (روی هاست)

```dotenv
APP_ENV=production
APP_DEBUG=false                 # هرگز true نباشد: جزئیات خطا و تنظیمات لو می‌رود
APP_URL=https://ilnia.ir        # نشانی واقعی، با https
LOG_LEVEL=error

SESSION_DRIVER=database
SESSION_SECURE_COOKIE=true      # کوکی ورود فقط روی HTTPS
QUEUE_CONNECTION=database
CACHE_STORE=database

SMS_DRIVER=kavenegar
KAVENEGAR_API_KEY=...           # فقط روی هاست؛ هرگز در Git
ZARINPAL_MERCHANT_ID=...        # خالی = پرداخت آنلاین خاموش
ZARINPAL_SANDBOX=false

# فقط اگر سایت پشت CDN یا پروکسی است (مثلاً ابر آروان یا کلادفلر):
# TRUSTED_PROXIES=*
```

- [ ] `APP_KEY` روی هاست با `php artisan key:generate` ساخته شده و **با `.env` محلی یکی نیست**.
- [ ] `.env` بیرون از پوشهٔ `public/` است و از اینترنت خوانده نمی‌شود. با باز کردن `https://ilnia.ir/.env` در مرورگر چک کن: باید خطای ۴۰۴ بدهد.
- [ ] `.env` در Git نیست. این را `.gitignore` تضمین می‌کند.

## ۲. HTTPS
- [ ] گواهی SSL روی هاست فعال است. بیشتر هاست‌ها گواهی رایگان Let's Encrypt دارند.
- [ ] نسخهٔ `http://` در تنظیمات هاست به `https://` ریدایرکت می‌شود.
- وقتی `APP_URL` با `https://` شروع شود، سایت همهٔ لینک‌ها و ریدایرکت‌ها را با HTTPS می‌سازد (`AppServiceProvider`) و هدر HSTS هم فرستاده می‌شود.
- **پشت CDN:** اگر سایت پشت ابر آروان، کلادفلر یا پروکسی دیگری است، `TRUSTED_PROXIES` را تنظیم کن. **این مهم است:** بدون آن، همهٔ بازدیدکننده‌ها با IP خود CDN دیده می‌شوند، محدودیت ارسال کد ورود برای همه با هم پر می‌شود و هیچ‌کس نمی‌تواند وارد شود.

## ۳. محدودیت تعداد درخواست (rate limit)
| بخش | محدودیت | محل |
|---|---|---|
| ارسال کد ورود | یک بار در هر ۶۰ ثانیه؛ ۵ بار در ساعت برای هر موبایل؛ ۲۰ بار در ساعت برای هر IP | `OtpService` |
| وارد کردن کد | ۵ تلاش غلط برای هر کد؛ ۳۰ تلاش در ۱۰ دقیقه برای هر IP؛ اعتبار کد ۲ دقیقه | `OtpService` |
| ورود به پنل مدیریت | ۵ تلاش در دقیقه | Filament (پیش‌فرض) |
| پرداخت دوباره | ۱۰ بار در دقیقه | `routes/web.php` |
| بازگشت از درگاه | ۳۰ بار در دقیقه برای هر IP | `routes/web.php` |

## ۴. دسترسی پنل `/admin`
- فقط کاربرهایی که `is_admin = true` دارند وارد پنل می‌شوند (`User::canAccessPanel`). مشتری عادی خطای ۴۰۳ می‌بیند.
- `is_admin` از هیچ فرمی قابل تغییر نیست. فقط دستور `php artisan ilnia:make-admin` آن را روشن می‌کند.
- [ ] رمز مدیر قوی است (حداقل ۱۲ حرف) و جای دیگری استفاده نشده.
- [ ] فهرست مدیرها را گاهی چک کن. دستور `ilnia:security-check` تعدادشان را نشان می‌دهد.

## ۵. پرداخت
- مبلغ فقط از سفارش ذخیره‌شده در سرور خوانده می‌شود، تأیید با verify سمت سرور است و یک پرداخت دو بار ثبت نمی‌شود (`PaymentService`، `docs/ARCHITECTURE.md`).
- [ ] اولین پرداخت واقعی را با مبلغ کم تست کن (فاز ۴).
- [ ] قبل از انتشار، یک برنامه‌نویس باتجربه کد پرداخت و امنیت را بررسی کند (فاز ۴، کار صاحب پروژه).

## ۶. هدرهای امنیتی (خودکار)
`SecurityHeaders` این هدرها را روی همهٔ صفحه‌ها می‌گذارد:
- `X-Frame-Options`: سایت داخل قاب سایت دیگری نمایش داده نمی‌شود.
- `X-Content-Type-Options`
- `Referrer-Policy`: شمارهٔ سفارش در آدرس به سایت‌های دیگر نمی‌رسد.
- `Permissions-Policy`
- `Strict-Transport-Security`: فقط روی HTTPS فرستاده می‌شود.

**Content-Security-Policy هنوز گذاشته نشده**، چون Livewire و Alpine اسکریپت درون‌خطی دارند و CSP نادرست تسویه‌حساب را از کار می‌اندازد. بعد از انتشار با دقت اضافه شود.
